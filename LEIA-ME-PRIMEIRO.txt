📊 MODELO DE DADOS
═══════════════════════════════════════════════════════════════════════════════

8 Entidades Principais:

  1. CLIENTE              - Usuários da plataforma
  2. ENDERECO            - Endereços do cliente (1:N)
  3. CONTA               - Conta bancária do cliente (1:1)
  4. PEDIDO              - Pedidos de compra
  5. ITEM_PEDIDO         - Itens dentro de um pedido
  6. PRODUTO            - Catálogo de produtos
  7. BOLETO             - Instrumento de pagamento
  8. EXTRATO            - Histórico de transações

Relacionamentos:
  • Cliente (1:N) Endereco
  • Cliente (1:1) Conta
  • Cliente (1:N) Pedido
  • Pedido (1:N) ItemPedido
  • Pedido (1:1) Boleto
  • Conta (1:N) Extrato
  • ItemPedido (N:1) Produto

🔐 SEGURANÇA
═══════════════════════════════════════════════════════════════════════════════

✓ Autenticação via JWT
  - Token com expiração (24h padrão)
  - Claims: sub (clienteId), roles, iat, exp

✓ Senhas com BCrypt
  - Hash seguro, não reversível
  - Salt único por senha

✓ Autorização por Papéis
  - ROLE_USER    (clientes)
  - ROLE_ADMIN   (administradores)

✓ Validação em Múltiplas Camadas
  - DTO com @Valid
  - Bean Validation
  - Verificações em Service

✓ Endpoints Protegidos
  - Requerem Authorization header
  - Retorna 403 Forbidden sem token

🎯 FLUXO PRINCIPAL: Do Pedido ao Pagamento
═══════════════════════════════════════════════════════════════════════════════

1. Cliente se cadastra
   └─ POST /api/auth/register
   └─ Cliente + Conta criados automaticamente

2. Cliente navega catálogo
   └─ GET /api/produtos

3. Cliente cria pedido
   └─ POST /api/pedidos
   └─ Status: CRIADO

4. Pedido é reservado
   └─ PATCH /api/pedidos/{id}/reservar
   └─ Status: RESERVADO

5. Boleto é gerado
   └─ POST /api/boletos/gerar/{pedidoId}
   └─ Código 44 dígitos, vencimento +3 dias

6. Boleto é pago
   └─ PATCH /api/boletos/{id}/pagar
   └─ Débito cliente, crédito empresa
   └─ Extrato criado

7. Cliente consulta extrato
   └─ GET /api/contas/{id}/extrato
   └─ Histórico com saldos antes/depois
